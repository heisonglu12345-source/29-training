# OrderHub Bug 修復流程

依照以下流程處理使用者描述的 bug：

1. 根據症狀推測涉及的頁面與流程，先向使用者確認對症狀的理解。
2. 要求或協助使用者在頁面重現，記錄頁碼、金額、庫存或錯誤訊息等具體觀察。
3. 從 Controller 追到 Service 與 Repository，定位根因。
4. 說明根因與最小修復方案，等待使用者確認後才修改檔案。
5. 只修復目前 bug，不順手重構無關程式碼。
6. 使用 `code-reviewer` 審查變更。
7. 補一個能防止問題再次發生的回歸測試，並確認測試能驗證原本的錯誤行為。
8. 使用 `test-runner` 執行 `dotnet test`，確認全部測試通過。
9. 提醒使用者回到頁面實測，確認原始症狀已消失。
10. 使用者確認後，以「症狀 → 根因 → 修法」格式準備 commit message；取得明確同意後才 commit。
